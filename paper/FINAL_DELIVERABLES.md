## 1. Figure-data CSVs (2 + 1), generated by `scripts/analyze.py`, committed under `paper/figures_data/`

**Status: code implemented and smoke-tested (commit `74dcd1e`) against a
mid-run `multiturn_state.json` snapshot and a mock final-retiming JSON —
not yet run for real. Run it again after turn 10 / cutoff and commit the
actual CSVs then.**

### `fig1_ever_correct.csv` — Figure 1 (ever-correct@turn) data

```
hardware,turn,lang,model,condition,ever_correct,n
sm_120,1,cuda,gpt-oss-120b,0shot,0,160
sm_120,1,cuda,gpt-oss-120b,docinject,42,85
...
```

- `condition` ∈ {`0shot`, `docinject`}; all turns 1..final turn present.
- A terminated chain stays in its group and keeps contributing its
  (already-monotonic) ever-correct value at every subsequent turn — no
  special-casing needed, this falls out of the "ever correct by turn t"
  definition automatically.
- `ever_correct` MUST be recomputed directly from `history[].correctness`
  (never from `chain["best_turn"]`, which undercounts a chain that was
  correct but hit a timing exception) — this is the same fix applied to
  `scripts/multiturn.py cmd_report`'s PRIMARY(a) table and to the
  workstream-split section added 2026-08-22 (commit `63328b3`).
- Generator: `analyze.fig1_ever_correct_rows()`.

### `fig2_speedup.csv` — Figure 2 (best-speedup@turn) data

```
hardware,turn,lang,model,n_timed,geomean_best_speedup
```

- In-chain (turn-loop) timing trajectory — the same basis as the turn
  reports' §2 PRIMARY(b) table. This is **appendix/trajectory-only**, not a
  citable speedup number (see next item).
- Generator: `analyze.fig2_speedup_rows()`.

### `final_retiming_summary.csv` — the paper's ONLY citable speedup source

```
lang,model,condition,n,geomean,fast_1
```

- Built from a `scripts/final_retiming.py` output JSON
  (`results/eval/final_timing_*.json`), not from `multiturn_state.json`
  turn-loop timing.
- **This file is the sole source the paper's reported speedup/fast_1
  numbers may cite.** `fig2_speedup.csv` and any `best_speedup` field in
  `multiturn_state.json` are stimulus-only (measured under varying
  concurrent-load conditions across the run) — see CLAUDE.md item 4 and
  `final_retiming.py`'s own docstring.
- Generator: `analyze.final_retiming_summary_rows()`.

**How to run once turn 10 / cutoff has happened:**

```
source scripts/env.sh && source .venv/bin/activate
python scripts/analyze.py \
  --multiturn-state results/eval/multiturn_state.json \
  --final-retiming results/eval/final_timing_<timestamp>.json \
  --figures-dir paper/figures_data
git add paper/figures_data/*.csv
git commit -m "paper: final figure-data CSVs (turn 10 / run completion)"
```

## 3. Final re-timing pass

**Status: implemented (`scripts/final_retiming.py`, checkpoint/resume in
commits `779aeeb`/`2aedaea`) and wired into the automatic post-loop tail of
`logs/multiturn/run_all_turns.sh`. Runs automatically once the loop reaches
a clean exit — no manual step needed unless it FATALs (power/turbo drift
mid-pass, see its own error message) and needs a manual re-run.**

- After turn 10 completes (or the run hits the 2026-08-25 06:00 KST
  cutoff), re-measure every chain's best-so-far correct kernel plus the
  canonical per-task eager-fp16 PyTorch baseline, in one batch, under a
  single fixed power/turbo/GPU-exclusive condition (32-task primary set +
  appendix-only tasks both included, primary set flagged via
  `is_primary_32`).
- Checkpointed every `--checkpoint-every` (default 25) chains; resumable
  from a partial output as long as the power/turbo stamp still matches
  (otherwise it discards the partial and starts clean rather than mixing
  incomparable halves).
- **Before this pass starts**, `run_all_turns.sh` now force-commits and
  pushes `multiturn_state.json` to `origin/master` as a one-time remote
  backup (PI instruction 2026-08-22, given the crash frequency this run has
  shown — see commit `b3c7923`). Best-effort: logs loudly on failure but
  does not block the re-timing pass itself.
- Output: `results/eval/final_timing_<timestamp>.json` → feeds
  `final_retiming_summary.csv` above.
